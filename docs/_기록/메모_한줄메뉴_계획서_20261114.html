1. 목적

세무사님 원문(11-14): "자. 그렇게 해서 메뉴표시줄 1줄에 모두 넣는 것으로 계획서를 만들라" → "관리메뉴를 한 줄로 하라는 것이다. 편집메뉴는 기존대로 두라"

앞서 검토하신 네 가지(글/손 단추 하나 · 저장 단추 합치기 · 「양식」 기호 지우기 · 「보기」를 작성관리 기호로)를 반영하고, 지금 두 줄로 나뉜 관리 단추를 한 줄로 모읍니다. 서식 단추 줄(글)과 펜 도구 줄(손글씨) 같은 편집 메뉴는 지금 그대로 둡니다.

첫째 판은 「모두」를 편집 메뉴까지로 넓혀 읽어 서식·펜 도구 줄까지 한 줄에 넣었습니다 — 이 판에서 바로잡았습니다.

7. 만드는 순서 (확정 뒤)

  1. 메모 화면 원본(memo.html) — 관리 두 줄을 한 줄로, 관리 단추 다섯 가지 바꿈, 저장 고르기, (㉡에 따라) 태그 칩 자리. 편집 줄 둘은 손대지 않음
  2. 모양(style.html) — 관리 한 줄·찾기 칸 폭
  3. 옛 이름표 잇기 그대로 확인(떠 있는 ✍ · 폰 현장 도구 · 넥스 → [손]으로 열림)
  4. 사용 설명서(manual.html) 메모 절 글 고침
  5. 화면 다시 조립 → 가짜 서버 시험 사본

8. 확인 방법

  • 가짜 서버 시험 사본에서 PC(1280)·태블릿(768·1024)·폰(375) 폭으로 실제 클릭·입력: [글]↔[손] 오가기(쓰던 글·그림 그대로) · 찾기·태그 칩 거르기 · 양식 불러오기 · ◧↔◨ · [저장] → 사건에 넣기 끝까지 / 일반메모로 폴더 골라 끝까지 · 불러온 일반메모 고쳐 저장
  • 숫자: 관리 줄이 폭마다 한 줄인지(getBoundingClientRect 높이), 편집 줄 두 개는 바꾸기 전과 높이·단추 수가 같은지
  • 떠 있는 ✍로 들어가면 [손]으로 열리는지
  • 화면만 바뀜 — 서버는 그대로(서버 고침 없음)
