4. 정하실 것 — 권장안

  • 가(화면 먼저)를 먼저 — 사건 저장에 이미 쓰는 같은 장치를 장부에도 씀, 서버 변경 없음.
  • 나·다는 가를 쓰신 뒤에도 느리다고 하시면 다시 여쭘(넥스가 느려지는 값이 있음).

4-1. 한 것 (11-13 오후, 세무사님 "원인을 제대로 분석해서 더이상 속도문제가 대두되지 않도록 하라 … 창을 여러개 열어서 … 동시에 처리")

  • 원인(확인한 것): 서버 입구는 일 전에 아무것도 하지 않음(빈 호출 6.8~11.6초) · 최상위에서 서버 기능을 부르는 줄 없음 → 바닥은 구글이 코드 전체(함수 5.95MB·값 1.14MB)를 매번 싣는 시간. 10-17 3MB(3~5초) → 지금 8.8MB(7.5초 넘음) — 지난 검토들은 서버 안 일만 줄이고 크기는 지키지 않았음. 쓰기는 잠금 때문에 이 서버 한 곳이라, 누를 때마다 바닥+일(13~16초)을 기다렸음.
  • 가(화면 먼저) 만듦: 장부 값 넣기·확인·보류·무시·되돌리기 → 사건 저장과 같은 장치. 운영에서 가상 시험 사건으로: 「확인」 누른 뒤 화면 바뀜 0.009초(전 13~16초), 서버 저장 13초 뒤 같은 값으로 확정, 이어 누르기·저장 중 다른 줄 「⋯」 펼침이 서버 답 뒤에도 그대로. 되돌리기는 서버 값을 알아야 해 「저장 중」 띠 뒤 서버 값으로.
  • 여러 창: 같은 사건은 차례로·다른 사건은 따로 뒤에서 보냄, 다른 창이 보내는 중인 것은 2분 넘게 답이 없을 때만 다시 보냄(이미 있던 장치), 기기에 남긴 지난 값·보낼 함은 창끼리 같이 씀.
  • 크기 지킴이: 올리기 전 검문(tools/change-check.js)이 job 서버가 기준(tools/server-size-baseline.json, 8.80MB)보다 0.1MB 넘게 커지면 막음 — 늘리려면 기준 파일에 까닭을 적어야 함.
  • 나(쓰기 서버)·다(덜어내기)는 하지 않음 — 넥스가 같은 장부에 써서 잠금이 갈리거나(나) 효과가 작음(다).

5. 확인 방법

  • 가상 시험 사건을 새로 만들어 장부 「확인」·값 넣기·되돌리기를 실제로 누르고, 화면이 바뀌는 데 걸린 시간과 서버 저장 뒤 같은 값인지 재고, 시험 사건은 지움.
  • 서버가 거절하는 경우(넥스가 정한 값 고치기)를 일부러 만들어 되돌아가며 까닭이 뜨는지.
