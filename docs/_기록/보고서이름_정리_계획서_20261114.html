고친 까닭: 첫 판은 보고서를 종류(용도)로 가르지 않고 「원본은 모두 보고서_내부」로 묶었습니다. 둘째 판은 종류로 폴더를 갈랐습니다. 이 판은 말씀대로 폴더는 「보고서」 하나로 합치고, 내부·외부는 보고서 종류(이름)로 가립니다.

승인해 주시기 전에는 코드도 드라이브 파일도 손대지 않습니다. 아래 숫자는 오늘 제가 코드와 드라이브(J: 고객사건)를 직접 열어 센 것입니다.

4. 고칠 곳 — 가. 서버 한 곳으로 (폴더 하나 + 이름표 하나 + 함수 하나)

  1. 보고서 종류표 하나 + 함수 하나(Code.js): 9가지 종류마다 「이름 · 내부/외부 · 세부명칭 필수 여부」를 서버 표 하나에 둡니다. 함수는 세 가지를 정합니다.
    • 종류·세부명칭 → 정식 이름
    • 사건 → 「보고서」 폴더(없으면 만듦)
    • 파일 이름 → 내부/외부(고객에게 보여도 되나)
    서버 옛 표(「참고보고서」)는 이 표로 바꿉니다.
  2. 폴더 이름 한 곳: 「보고서_내부」·「보고서_외부」 두 상수를 「보고서」 하나로 바꿉니다. 바꾸는 순서는 드라이브 규칙대로입니다.
    • ① 코드가 「보고서」와 옛 두 이름을 모두 찾게 하고 배포합니다.
    • ② 사건 폴더를 합칩니다.
    • ③ 옛 이름 찾기를 남겨 둡니다(사건 목록에 없는 옛 폴더 대비).
    바뀌는 자리(직접 센 것): 서버 Code.js 약 50곳 · AiLeadLive.js 9 · KnowHow.js · Federation.js · BgQueue.js · 화면(보고서 탭·처리개요·넥스 창) · 부가 서버(gs-extra·gs-light 생성 파일) · 직결(cloudrun 폴더 판정) · 점검 도구(knowhow-check). 9-16 1회용 개명 함수는 다시 돌지 않게 막습니다(옛 「보고서」를 「보고서_외부」로 바꾸는 함수라 거꾸로 돌면 안 됨).
  3. 보고서 탭: 세부명칭은 지금처럼 화면이 묻습니다. 저장할 때 종류·세부명칭을 같이 보내면 서버 함수가 마지막에 이름을 정합니다. 원본·발행본·PDF가 같은 「보고서」 폴더에 놓이도록, 원본·발행본 짝 찾기(지금은 「부모의 부모 → 보고서_외부」)를 같은 폴더 기준으로 고칩니다. 화면 이름표는 서버 표를 받아 씁니다(이미 부르는 사건 하위폴더 조회에 실어 보내므로 서버 호출이 늘지 않음).
  4. 넥스 저장 두 길(문서 저장 · 구글 문서로 내보내기, 사건이 연결된 대화):
    • 「보고서 종류」·「세부명칭」 칸을 더합니다.
    • 보고서면 서버 함수가 정식 이름·「보고서」 폴더로 저장합니다. 넥스가 다른 이름·자리를 줬으면 바꿔 저장하고, "정식 이름 ○○로 「보고서」에 저장했다(넥스가 준 이름: …)"를 넥스에게 돌려줍니다.
    • 종류를 안 줬는데 이름에 검토·보고서·의견 등이 있으면 보고서로 봅니다. 종류를 이름으로 가릴 수 없으면 저장하지 않고 넥스에게 종류를 달라고 돌려줍니다. 개별검토서인데 세부명칭이 없을 때도 같습니다.
    • 넥스가 옛 path(「보고서_내부」·「보고서_외부」)를 주면 「보고서」로 읽습니다.
    • 저장 방식은 지침 5절 그대로입니다(같은 이름 갱신 · 직전 판 「_이전판」). 옛 이름 검토서가 하나 있으면 새로 만들지 않고 그 파일을 정식 이름으로 바꿔 갱신합니다(파일 ID 그대로).
  5. 넥스 안내 글: 도구 설명 두 개, 보고서 재료 도구(report_parts), 넥스 보고서 안내(AiLeadLive.js)의 path·이름 예시를 「보고서」·정식 이름으로 바꾸고 「종류 → 이름」 규칙 한 줄을 적습니다. 검토서를 언제 만드는지는 적지 않습니다. 11-14 세무사님 새 결정("내가 검토서를 만들라고 한 사건만 검토서가 생성되고 …")에 맞춰 메인 세션이 지침 5절과 함께 바꿉니다. 업무관리자 지침 파일은 이 일에서 손대지 않습니다. 지침 5절의 「보고서_내부」 글자도 메인 세션에 알려 함께 고치게 합니다.
  6. 고객 창구(my.netax.kr)·발행: 고객 창구 목록은 「보고서」 폴더에서 외부보고서 이름의 .html만 내보냅니다. 발행 단추는 지금처럼 내부보고서를 막고, 같은 폴더에 .html을 만듭니다. 보고서 모음의 「발행됨」 표시도 폴더 이름이 아니라 「외부보고서 이름의 .html이 있는가」로 바꿉니다.
  7. 배포마다 스스로 보는 점검 한 줄(Federation.js 소통 이음매):
    • 「개별검토서+쟁점 → 보고서/개별검토서_쟁점.md」, 「자문보고서 → 보고서/자문보고서.md」로 나오는지
    • 「세부명칭 없는 개별검토서」는 거절하는지
    • 「종합검토서.html」은 고객 창구에 안 나가고 「자문보고서.html」만 나가는지
  8. 앞으로 만들 밤 갱신(메인 세션 계획)은 이 함수만 부르면 같은 이름·자리로 갑니다. 함수 이름은 메인 세션에 넘깁니다.

5. 정하실 것 (권장안 먼저)

  1. 옛 외부보고서 발행본 .html 5건(노영환 신고보고서 · 방신영·최은진 자문보고서 · 임의선 자문보고서_납세자·_의뢰인, 지금은 사건 폴더 맨 위 — 고객 창구에 안 보임)을 「보고서」로 옮기면 고객 창구에 새로 보이게 됩니다.

    권장: 그대로 사라지게 둡니다. 고객에게 일부러 보여 주신 것이면 자문보고서로 이름을 바꿔 계속 보이게 합니다.

7. 순서 · 확인 방법

  1. 가(서버 한 곳) 고침 → 문법 검사 → 정식 이름·자리·고객 보임 함수 단독 시험(9종류 × 세부명칭 있음/없음 × .md/.html).
  2. 배포: 화면 다시 조립 → clasp push(「Pushed」 확인) → 배포(「Deployed @NNNN」 확인, 자동 모드가 막으면 세무사님 cmd 한 줄) → 부가 서버 → 직결 다시 빌드. 배포 잠금·origin/main 확인은 배포 규칙대로 합니다. 커밋·푸시는 말씀하실 때만 합니다.
  3. 확인(처음 보는 가상사건 하나를 새로 만들어):
    • 보고서 탭에서 종합검토서·개별검토서·자문보고서·검토조서를 새로 저장 → 모두 「보고서」에 정식 이름으로 가는지.
    • 자문보고서 발행 → 같은 폴더에 .html이 생기고, 고객 창구 목록에 자문보고서.html만 뜨는지(종합검토서는 안 뜸).
    • 넥스 저장(5절 ④대로)에 엉뚱한 이름·옛 path를 줘도 정식 이름·「보고서」로 가는지.
    • 같은 문서를 다시 저장 → 같은 파일 갱신·「_이전판」 보관.
    • 현황표가 그 종합검토서를 찾는지.
  4. 나(합치기·정리 도구): 미리 보기를 띄워 드림 → 승인 → 적용 → 합친 폴더·옮긴 파일 몇 개를 ID로 다시 열어 같은 것인지, 자문 장부·현황표·발행본 짝·고객 창구 목록이 다시 찾는지, 되돌리기 한 건 시험.
  5. 가상사건 흔적 지우기(드라이브 휴지통) · 할 일 장부 · 결과 보고.
