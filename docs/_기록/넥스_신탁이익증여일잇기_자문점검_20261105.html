넥스 점검 227 — 「신탁이익의 증여(상증법 §33·시행령 §25) — 증여일(실제 지급일·위탁자 사망일·약정일·최초 지급일) 판정을 「증여일」 묶음에 잇기」 자문점검 · 2026-11-05

세액 계산기(calculate_trust_income_gift_tax)는 일반 증여세 산식이라 맞았으나, §33 신탁이익의 증여일을 정하는 시행령 §25①(실제 지급일 원칙, 사망·약정·분할 예외)은 어느 도구도 가르지 않고 안내 글로만 있었습니다. 「증여일」 묶음에 종류 「신탁이익」 갈래를 더했습니다.

1. 사건 (시험용 가정)

  • 아버지가 신탁회사에 3억을 맡기고 아들을 수익자로 지정. 견주기: 2026-03-10 실제 지급 / 받기 전 2025-12-01 아버지 사망 / 2026-01-31 약정일까지 미지급 / 5년 분할(최초 2026-02-01, 이번 2026-08-01) / 위탁자가 해지권 보유 / 날짜 모름.

2. 법 (원문을 직접 읽음 — 상증법 20260102·시행령 20261001 시행판)

  • §33①: 위탁자가 타인을 수익자로 지정한 신탁에서 수익자가 원본(1호)·수익(2호)을 받으면 대통령령이 정하는 날을 증여일로 그 권리의 가액을 증여재산가액으로. ②: 수익자 미특정·미존재면 위탁자(상속인)를 수익자로, 특정된 때 새 신탁. 시행령 §25①: 실제 지급되는 날 — 다만 1호 받기 전 위탁자 사망 → 사망일, 2호 약정일까지 미지급 → 약정일, 3호 여러 차례 → 최초 지급일(계약일에 미확정이거나 위탁자가 해지·수익자 변경·잔여재산 귀속권으로 실질 지배하면 각 실제 지급일). ②: 여러 차례면 §61 준용 평가.

3. 도구가 놓치던 것

  • 「증여일」 묶음(§24)엔 신탁이익 갈래가 없어 종류를 「기타」(인도일)로 넣거나 특례조문 §33으로 넣으면 「그 조문 계산기의 증여일을 쓸 것」으로만 돌려보냈는데, 그 계산기는 증여일을 셈하지 않는다 — 사망일·약정일·최초 지급일 예외를 넥스가 손으로 정해야 했다.

4. 고친 것

  • gs-backend/JudgeMore.js judgeGiftAcquisitionDate_: 종류 「신탁이익」 갈래(실제지급일·위탁자사망일·약정지급일·분할지급·최초지급일·이익미확정·위탁자지배) — §25① 본문·1~3호(단서 포함) 순서로 증여일·근거·신고기한·평가기간·10년 합산 시작일을 냄, §33②·§61 평가 알림.
